# Final pre-submission QA

Run the [README quick start](../../README.md#quick-start) from a fresh clone and repeat the browser checks in a private window on the hosted URL. Record which mode you tested. Stub mode verifies the browser flow with simulated events. Live claims require the corresponding sandbox evidence.

| Area | Steps | Expected result |
| --- | --- | --- |
| Mandates | Open **Mandates**. Set a per-transaction cap above the total and continue. Correct the caps, select a merchant and **24h**, then continue through sandbox approval or **Simulate PayPal approval** in stub mode. Click **Sign and save mandate**. | Invalid caps show a validation error. Saving becomes available after buyer approval. The saved mandate appears as **Active**, and its JSON contains an approved order ID and signature. |
| Live Ledger | Select the saved mandate and run **Happy path**, **Poisoned page**, and **Budget splitting**. Switch between **Payments** and **All events**, filter by decision, and group by merchant. Pause while events arrive, then resume. | New rows arrive without refresh. The demo shows an allow and the two block paths. Each view, filter, and group shows the corresponding rows. Pause freezes the view and resume reveals buffered events. |
| Approvals | Open **Approvals**. Start an approval and cancel the dialog. Approve one pending payment, then reject another with a reason. Check the sidebar count and filter the ledger for each human event. | Cancel leaves the payment pending. The sidebar count updates after submission, and confirmed reviews appear only after the audit event. The ledger shows both human decisions and the rejection reason. In live mode, verify checkout if a PayPal approval link or order is supplied. |
| Payment Detail | Open the poisoned-page row and click **Open full timeline**. Expand **Raw JSON payload** on the scan or decision. Open an unknown payment route. | The summary matches the selected payment, and the timeline keeps the stored event order. The injection snippet is highlighted and the raw payload expands. An unknown payment shows an empty or not-found message. In live mode, verify the displayed PayPal IDs against the corresponding sandbox events. |
| Benchmark | Open **Benchmark** and inspect run details, block rate, false-positive rate, latency, catching layers, and ablation. Filter **Scenario results** by class, result, and layer. | Charts and filtered rows match the loaded report. The bundled report displays **Sample data**. Before making measured claims, verify a genuine report against its source, including observed versus planned and unresolved counts per arm. Check that unavailable metrics display as unavailable and remain distinct from measured zeros. If those checks fail, leave measured claims out of the submission. |
| Hosted cold start | After the sandbox gateway has gone idle, open the hosted dashboard in a private window. Observe startup, then open a direct payment URL. If startup exhausts retries, use **Retry connection** after the service is available. | Live mode shows **Waking up the server** and opens the dashboard after the health probe succeeds. Direct routes load through the static rewrite. The hosted stub opens directly and verifies the static deployment only. |

For each failure, record the commit, mode, steps, and observed result. Fix and rerun any failure that affects the evidence in the submission.
